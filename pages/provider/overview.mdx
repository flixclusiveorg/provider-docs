# Overview

Learn the high-level architecture of a Flixclusive provider.

## What makes a provider?

At its core, a provider in Flixclusive consists of:

### 1) Provider entry class

The entry class is your provider’s main class. It must:

- Extend [`ProviderPlugin`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider/-provider-plugin/index.html)
- Be annotated with [`@FlixclusiveProvider`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider/-flixclusive-provider/index.html)

<Note>
    `Provider` still exists as a deprecated typealias to `ProviderPlugin`. For new code and docs,
    prefer `ProviderPlugin`.
</Note>

`ProviderPlugin` is responsible for exposing capability APIs via getters such as:

- `getCatalogApi(context)`
- `getSearchApi(context)`
- `getMetadataApi(context)`
- `getMediaLinkApi(context)`
- `getCrossMatchApi(context)`
- `getTrackerApi(context)`

### 2) Provider metadata (generated by Gradle)

Provider identity + presentation data is represented by:

- [`ProviderMetadata`](https://flixclusiveorg.github.io/core-stubs/model-provider/com.flixclusive.model.provider/-provider-metadata/index.html) (formerly `ProviderData`)
- [`ProviderManifest`](https://flixclusiveorg.github.io/core-stubs/model-provider/com.flixclusive.model.provider/-provider-manifest/index.html) (runtime manifest)

These are generated from your `flxProvider { ... }` configuration in Gradle.

### 3) Capability APIs (recommended)

Instead of a single monolithic API class, modern providers implement focused capability contracts:

- [`CatalogProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-catalog-provider-api/index.html)
- [`SearchProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-search-provider-api/index.html)
- [`MetadataProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-metadata-provider-api/index.html)
- [`MediaLinkProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-media-link-provider-api/index.html)
- [`CrossMatchProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-cross-match-provider-api/index.html)
- [`TrackerProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider.capability/-tracker-provider-api/index.html)

<Note>
    [`ProviderApi`](https://flixclusiveorg.github.io/core-stubs/provider/com.flixclusive.provider/-provider-api/index.html)
    still exists for backward compatibility, but it is deprecated.
</Note>

These two components work together seamlessly to create a complete provider experience. While the API handles the *how* of content delivery, the ProviderData manages the *what* and *who* of your provider.

## How they work together

Think of it this way:
- `ProviderPlugin` is the entry point the app loads.
- Capability APIs are the “engines” that do the work (search, catalogs, metadata, links, etc.).
- `ProviderMetadata` / `ProviderManifest` describe the provider (name, id, version, repository, etc.).
